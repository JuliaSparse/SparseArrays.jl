Sparse Arrays

The SparseArrays stdlib module provides sparse vectors and sparse matrices: arrays with enough zeros that storing only the other entries saves space and time compared to dense arrays.

Sparse Vectors and Matrices

Compressed Sparse Column (CSC) Sparse Matrix Storage

In Julia, sparse matrices are stored in the Compressed Sparse Column (CSC) format. Julia sparse matrices have the type SparseMatrixCSC{Tv,Ti}, where Tv is the type of the stored values, and Ti is the integer type for storing column pointers and row indices. The internal representation of SparseMatrixCSC is as follows:

struct SparseMatrixCSC{Tv,Ti<:Integer} <: AbstractSparseMatrixCSC{Tv,Ti}
    m::Int                  # Number of rows
    n::Int                  # Number of columns
    colptr::Vector{Ti}      # Column j is in colptr[j]:(colptr[j+1]-1)
    rowval::Vector{Ti}      # Row indices of stored values
    nzval::Vector{Tv}       # Stored values, typically nonzeros
end

CSC storage makes access to the entries of a column fast, and access by row considerably slower. Inserting previously unstored entries one at a time is slow as well, because every entry beyond the point of insertion has to be moved one place over. See Performance tips.

A SparseMatrixCSC may store explicit zeros. nnz counts the stored entries, including stored zeros, and count(!iszero, x) counts the numerical nonzeros. dropzeros, and the in-place dropzeros!, remove stored zeros.

julia> A = sparse([1, 1, 2, 3], [1, 3, 2, 3], [0, 1, 2, 0])
3×3 SparseMatrixCSC{Int64, Int64} with 4 stored entries:
 0  ⋅  1
 ⋅  2  ⋅
 ⋅  ⋅  0

julia> dropzeros(A)
3×3 SparseMatrixCSC{Int64, Int64} with 2 stored entries:
 ⋅  ⋅  1
 ⋅  2  ⋅
 ⋅  ⋅  ⋅

Arrays in CSC format from another application or library can be wrapped, without copying, with SparseMatrixCSC(m, n, colptr, rowval, nzval). Within each column the row indices must be sorted and unique, which the constructor does not check; the SparseMatrixCSC docstring lists the invariants. Arrays from a 0-based source, such as C or SciPy, need 1 added to colptr and rowval. To sort the row indices of a matrix A wrapped this way, transpose it twice, copy(transpose(copy(transpose(A)))).

The arrays of an m × n matrix in compressed sparse row (CSR) format are the CSC arrays of its transpose, so build the n × m matrix from them and transpose it:

julia> rowptr = [1, 3, 4]; colval = [1, 3, 2]; nzval = [1.0, 2.0, 3.0];  # 2 × 3 CSR

julia> copy(transpose(SparseMatrixCSC(3, 2, rowptr, colval, nzval)))
2×3 SparseMatrixCSC{Float64, Int64} with 3 stored entries:
 1.0   ⋅   2.0
  ⋅   3.0   ⋅

Sparse Vector Storage

Sparse vectors are stored in a close analog of the CSC format. They have the type SparseVector{Tv,Ti}, where Tv is the type of the stored values and Ti the integer type of the indices. The internal representation is as follows:

struct SparseVector{Tv,Ti<:Integer} <: AbstractSparseVector{Tv,Ti}
    n::Ti               # Length of the sparse vector
    nzind::Vector{Ti}   # Indices of stored values
    nzval::Vector{Tv}   # Stored values, typically nonzeros
end

Like a SparseMatrixCSC, a SparseVector can store explicit zeros. Its length is stored in the index type, so length(x) is a Ti rather than an Int.

Sparse Vector and Matrix Constructors

The simplest way to create a sparse array is spzeros, the equivalent of zeros for dense arrays:

julia> spzeros(3)
3-element SparseVector{Float64, Int64} with 0 stored entries

sparse builds a sparse matrix from a vector I of row indices, a vector J of column indices and a vector V of stored values, known as the COO (coordinate) format: sparse(I,J,V) returns S such that S[I[k], J[k]] = V[k]. Its vector equivalent sparsevec takes the index vector I and the values V, and returns R such that R[I[k]] = V[k]. Values given for the same position are added.

julia> I = [1, 4, 3, 5]; J = [4, 7, 18, 9]; V = [1, 2, -5, 3];

julia> S = sparse(I,J,V)
5×18 SparseMatrixCSC{Int64, Int64} with 4 stored entries:
 ⋅  ⋅  ⋅  1  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅   ⋅
 ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅   ⋅
 ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  -5
 ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  2  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅   ⋅
 ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  3  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅  ⋅   ⋅

julia> R = sparsevec(I,V)
5-element SparseVector{Int64, Int64} with 4 stored entries:
  [1]  =  1
  [3]  =  -5
  [4]  =  2
  [5]  =  3

findnz is the inverse of sparse and sparsevec: it returns the indices and values of the stored entries, including stored zeros. findall(!iszero, x) returns the indices of the nonzero entries of x, excluding stored zeros, and sparse also accepts the positions as such a vector of CartesianIndexes.

julia> findnz(S)
([1, 4, 5, 3], [4, 7, 9, 18], [1, 2, 3, -5])

julia> findnz(R)
([1, 3, 4, 5], [1, -5, 2, 3])

julia> sparse(findall(!iszero, S), [1, 2, 3, -5]) == S
true

sparse also converts a dense array to a sparse one, the Array constructor converts back, and issparse tells whether an array is sparse.

julia> sparse([1.0, 0.0, 1.0])
3-element SparseVector{Float64, Int64} with 2 stored entries:
  [1]  =  1.0
  [3]  =  1.0

julia> issparse(spzeros(5))
true

Other constructors build common matrices directly. sparse(I, n, n) is the identity, spdiagm places vectors on diagonals, and blockdiag puts matrices along the diagonal of a larger one. sprand and sprandn return a random vector or matrix in which each entry is stored with probability d, with uniformly or normally distributed values.

julia> spdiagm(0 => [1, 2, 3], 1 => [4, 5])
3×3 SparseMatrixCSC{Int64, Int64} with 5 stored entries:
 1  4  ⋅
 ⋅  2  5
 ⋅  ⋅  3

julia> blockdiag(sparse(2I, 2, 2), sparse([3 4])) == [2 0 0 0; 0 2 0 0; 0 0 3 4]
true

Sparse matrix operations

Sparse arrays support the operations of dense arrays, and a result is sparse unless it would store every entry. The subsections below give the rules for each kind of operation. indtype returns the index type Ti of a sparse array.

Arithmetic

OperationResult
A + B, A - B of sparse arrays, or with a Diagonal or Isparse, without the zeros it computes
A + D, A - D with a dense array Ddense
-A, 2A, A / 2sparse, with the stored entries of A
A / 0sparse with every entry stored, as 0 / 0 is NaN

Elementwise operations written with dot syntax, such as A .* B or A .+ 1, follow the rules of Broadcasting and map.

Indexing and assignment

Indexing with ranges, vectors, colons or a logical mask returns a sparse array: A[I, J] is a SparseMatrixCSC, and A[:, j], A[i, :], A[:] and A[mask] are SparseVectors. A scalar index returns the element, which is zero when it is not stored.

Assigning to a stored entry overwrites its value, even with zero: the entry stays stored until dropzeros! removes it. Assigning zero to an entry that is not stored changes nothing, and assigning any other value inserts the entry, which moves every stored entry after it. Indexing, and especially assignment, is therefore expensive one element at a time; see Performance tips.

Concatenation

[A B], [A; B] and [A B; C D] return a sparse array when at least one argument is sparse. A dense argument contributes its nonzeros, and a Diagonal or I its diagonal. sparse_hcat, sparse_vcat and sparse_hvcat return a sparse array even when no argument is sparse.

Reductions

sum(A) and the other reductions over all entries visit the stored entries only. Along a dimension, as in sum(A; dims = 2), the result is dense. With sparse = true, such as sum(A; dims = 2, sparse = true), it is sparse instead: it stores an entry only for the rows of A that store one, and its cost is proportional to the number of stored entries. prod, maximum, minimum, count, any, all and mapreduce accept the keyword too.

Broadcasting and map

broadcast (including dot syntax such as A .* B) and map over sparse arrays return a sparse result when the function maps zeros to zero. To decide, the function is evaluated once on the zeros of the arguments' element types:

Argumentsf(0, 0, ...) is zerof(0, 0, ...) is not zero
one sparse arraysparse, with the stored entries of the argumentArray
several sparse arrayssparse, storing only the nonzero resultsArray
sparse arrays and a scalarthe scalar is folded into f; then as abovesparse with every entry stored; Array if f is made only of + and -

So 2 .* A, abs.(A) and Float64.(A) keep the stored zeros of A, just as 2A, -A and float(A) do, while a combination of several sparse arrays drops the zeros it computes:

julia> A = sparse([1, 1, 2, 3], [1, 2, 2, 3], [1, 0, -2, 3])
3×3 SparseMatrixCSC{Int64, Int64} with 4 stored entries:
 1   0  ⋅
 ⋅  -2  ⋅
 ⋅   ⋅  3

julia> B = sparse([1, 1, 3], [1, 3, 3], [1, 5, -3]);

julia> A .+ B
3×3 SparseMatrixCSC{Int64, Int64} with 3 stored entries:
 2   ⋅  5
 ⋅  -2  ⋅
 ⋅   ⋅  ⋅

julia> iszero.(A)
3×3 BitMatrix:
 0  1  1
 1  0  1
 1  1  0

julia> A .+ 2
3×3 Matrix{Int64}:
 3  2  2
 2  0  2
 2  2  5

A result such as 2 .* A .+ 1 or A .^ 0, sparse with every entry stored, needs more memory than the equivalent Array; convert to dense first when that is what is meant.

Arguments that are not sparse arrays are handled as follows:

a Diagonal, Bidiagonal, Tridiagonal or SymTridiagonal matrixconverted to sparse

julia> A .* Diagonal([1, 2, 3])
3×3 SparseMatrixCSC{Int64, Int64} with 3 stored entries:
 1   ⋅  ⋅
 ⋅  -4  ⋅
 ⋅   ⋅  9

julia> typeof(A .* (1:3))
Matrix{Int64} (alias for Array{Int64, 2})

Whether a result is sparse depends on the value f(0, 0, ...), so its type is inferred only when the compiler can evaluate f there, as it does for the standard number types. A broadcast made only of +, - and * is always inferable.

map over sparse arrays always returns a sparse array, with every entry stored when f(0, 0, ...) is not zero. It requires all arguments to have the same shape, whereas broadcast expands singleton dimensions, with a sparse vector behaving as a one-column matrix.

broadcast!, map! and .= with a sparse destination overwrite its stored pattern with that of the result. The destination may also be one of the arguments, as in C .= C .+ C'. One exception: C .= 0 calls fill!, which keeps the pattern of C and sets the stored values to zero.

To apply a function to the stored values only, leaving the pattern untouched whatever the function returns for zero, broadcast over nonzeros instead:

julia> C = A .* B;

julia> nonzeros(C) .= nonzeros(C) .+ 9;

julia> C
3×3 SparseMatrixCSC{Int64, Int64} with 2 stored entries:
 10  ⋅  ⋅
  ⋅  ⋅  ⋅
  ⋅  ⋅  0

Products

The functions of LinearAlgebra have methods for sparse arrays. Products, dot, kron and the norms are implemented in this package, and the docstrings of those that behave differently for sparse arrays are listed under Linear algebra. The factorizations, and the solves that use them, call SuiteSparse and are described on the Sparse Linear Solvers page.

The result of * follows the other factor:

Product of a sparse matrix withResult
a Vector or a Matrixdense
a sparse vectorSparseVector
a sparse matrixSparseMatrixCSC
a Diagonal, Bidiagonal, Tridiagonal or SymTridiagonal matrixSparseMatrixCSC

mul!(y, A, x) writes the product into y, and mul!(y, A, x, α, β) computes A*x*α + y*β in place. A sparse destination is supported only for scaling by a Diagonal or a number. Products with A' and transpose(A) do not materialize the transpose when the other factor is dense or a sparse vector: see Lazy transpose and adjoint.

  • dot(x, y) of sparse or dense vectors and matrices visits the stored entries only, and dot(x, A, y) computes x' * A * y without forming A * y.

  • kron of two sparse arrays, or of a sparse array and a dense or Diagonal matrix, is sparse.

julia> A = sparse([2.0 1 0; 0 3 1; 1 0 4]); x = [1.0, 2.0, 3.0];

julia> y = similar(x); mul!(y, A, x)
3-element Vector{Float64}:
  4.0
  9.0
 13.0

julia> dot(x, A, x)
61.0

Norms and condition numbers

  • norm(A, p) treats A as a vector of its entries, so norm(A) is the Frobenius norm. opnorm(A, p) is the operator norm for p equal to 1, 2 or Inf; for p = 2 it is an iterative estimate.

  • cond(A, p) for p equal to 1 or Inf estimates the norm of the inverse from a factorization. The 2-norm condition number is not available; use cond(Array(A)) for a matrix small enough.

  • inv(A) throws, since the inverse is usually dense: solve with A \ B instead.

julia> norm(A, 1), opnorm(A, 1), opnorm(A, Inf)
(12.0, 5.0, 5.0)

Diagonals, triangles and permutations

  • tr(A) sums the diagonal, and diag(A, k) returns the kth diagonal as a SparseVector of the entries stored on it.

  • triu(A, k) and tril(A, k) return a new SparseMatrixCSC with the stored entries of a triangle, stored zeros included. triu! and tril! remove the other entries from A in place, changing its sparsity pattern.

  • permute applies a row and a column permutation in one pass.

Performance tips

Sparse code is fast when its cost is proportional to the number of stored entries, and the CSC layout determines which operations have that property.

Iterate over stored entries by column

The stored entries of column j are located at the positions nzrange(A, j) of rowvals(A) and nonzeros(A). Looping over the columns, and over that range within each column, visits every stored entry once and in memory order, without searching. For example, a matrix-vector product can be written as:

julia> A = sparse([1, 1, 2, 3], [1, 3, 2, 3], [1.0, 2.0, 3.0, 4.0]);

julia> function mymul(A::SparseMatrixCSC, x::Vector)
           y = zeros(promote_type(eltype(A), eltype(x)), size(A, 1))
           rows, vals = rowvals(A), nonzeros(A)
           for j in axes(A, 2), k in nzrange(A, j)
               y[rows[k]] += vals[k] * x[j]
           end
           return y
       end;

julia> mymul(A, [1.0, 10.0, 100.0]) == A * [1.0, 10.0, 100.0]
true

The same three accessors work on a SparseVector, which is treated as a single column, and on a view of whole columns such as @view A[:, j] or @view A[:, 2:3]. They are not defined for a triangular, Symmetric or Hermitian wrapper; work on its parent. getcolptr, getrowval and getnzval return the three storage vectors of a matrix themselves.

In contrast, scalar indexing A[i, j] has to do a binary search of column j for row i. A loop over all (i, j) of an m-by-n matrix therefore performs m * n searches, however few entries are stored.

Build a matrix from its entries in one call

Storing a value at a position that has no stored entry yet moves all the later entries, so filling spzeros(m, n) one element at a time takes time proportional to nnz(A) for each insertion. sizehint! avoids reallocating, but not moving the entries. Instead, collect the row indices, column indices and values in three vectors and call sparse once. Entries with the same position are added together, or combined with the function passed as the last argument, as in sparse(I, J, V, m, n, max).

To change many entries of an existing matrix, convert it to that form with findnz, work on the three vectors, and rebuild it.

Slice columns, not rows

A[:, j] copies one contiguous range of the stored entries. A[i, :] has to search every column for row i, so its cost grows with the number of columns even when the row is empty. When an algorithm works row by row, transpose the matrix once and work on the columns of the result. permutedims(A) and copy(transpose(A)) build the transposed matrix in time proportional to nnz(A).

julia> At = permutedims(A);

julia> At[:, 1] == A[1, :]
true

Choose a smaller index type

The index type Ti is used for the column pointers and for one row index per stored entry. With Float64 values, Int32 indices reduce the memory per stored entry from 16 to 12 bytes. Ti is taken from the index vectors given to sparse, can be given to spzeros, and an existing matrix is converted with the type constructor. Both dimensions have to be at most typemax(Ti), and the number of stored entries has to be less than typemax(Ti). Operations between matrices with different index types promote to the wider one, so use one index type consistently.

julia> A32 = SparseMatrixCSC{Float64,Int32}(A)
3×3 SparseMatrixCSC{Float64, Int32} with 4 stored entries:
 1.0   ⋅   2.0
  ⋅   3.0   ⋅
  ⋅    ⋅   4.0

julia> spzeros(Float64, Int8, 200, 200)
ERROR: ArgumentError: number of rows (m = 200) does not fit in Ti = Int8
[...]

Lazy transpose and adjoint

transpose(A) and A' do not copy; they return Transpose and Adjoint wrappers around A. What happens to a wrapper depends on the function:

  • Products with dense vectors and matrices (including mul!) and with sparse vectors, \, ==, and A'[i, :], which is a column slice of A, work on the wrapper without materializing the transpose.

  • Products with another sparse matrix, broadcasting (which includes + and -), map, concatenation, kron and findnz first copy the wrapper into a new SparseMatrixCSC, in time proportional to nnz(A), on every call.

  • Other functions, such as sum, norm and indexing other than by row, reach generic AbstractMatrix methods that visit the wrapper element by element.

When a transposed matrix is used more than once, or is passed to code outside the first group, materialize it with copy, or with sparse when the argument may or may not be a wrapper.

julia> A' * [1.0, 10.0, 100.0]
3-element Vector{Float64}:
   1.0
  30.0
 402.0

julia> copy(A')
3×3 SparseMatrixCSC{Float64, Int64} with 4 stored entries:
 1.0   ⋅    ⋅
  ⋅   3.0   ⋅
 2.0   ⋅   4.0

Keep results free of stored zeros

Assigning zero to a stored entry, and cancellation in a matrix product, leave explicitly stored zeros behind. They are harmless for correctness but are visited by every kernel. dropzeros! removes them, droptol! removes entries of small magnitude, and fkeep! keeps the entries for which a predicate of (i, j, v) is true, all in place.

julia> B = copy(A); B[1, 1] = 0; nnz(B)
4

julia> nnz(dropzeros!(B))
3

julia> fkeep!((i, j, v) -> i == j, B)
3×3 SparseMatrixCSC{Float64, Int64} with 2 stored entries:
 ⋅   ⋅    ⋅
 ⋅  3.0   ⋅
 ⋅   ⋅   4.0

Specialized Sparse Arrays

User-defined element types

A sparse array can store values of any type T. Building one from indices and values, copying, slicing, concatenating and permuting it, and reading a stored entry call nothing on the elements. Everything else rests on three things:

  • zero(T) is the value of an entry that is not stored. It is called on the type, not on a value, by whatever has to produce such an entry: indexing, setindex!, Matrix(A), a product with a dense array or a sparse vector, A + B, map, broadcasting and the reductions.

  • iszero(x) decides whether a value has to be stored. sparse of a dense array, dropzeros!, A + B, map and broadcasting call it. It falls back to x == zero(x).

  • The arithmetic of the operation itself: + and * for a product, isless for maximum, minimum and sort, and so on. sum adds the n entries that are not stored in one step, as zero(T) * n, so it also needs the product of an element with an integer.

The sparse kernels skip the entries that are not stored, so they assume that zero(T) behaves as a zero: x + zero(T) == x, and a product with zero(T) is zero. A type that defines zero, + and * is enough for most of the package, and every Number qualifies. For other element types:

  • Multiplying two sparse matrices needs only * and +, not zero(T). So a matrix of elements that have no zero(T), such as Matrix{Float64}, can be stored and multiplied by another, but not indexed at an entry that is not stored.

  • c * A, A * c and A / c are defined for a scalar c that is a Number. For any other element type, use map or broadcasting.

  • The sparse factorizations work in real and complex floating point. A matrix of integers or rationals is converted to Float64 first; a matrix of another element type, such as BigFloat, is rejected.

Sparse arrays with a fixed pattern

Experimental

fixed, FixedSparseCSC and FixedSparseVector are experimental and not exported.

Writing into a SparseMatrixCSC can change which entries it stores. W .= M .- γ .* J drops an entry of W wherever the difference is zero, and W[i, j] = v inserts one. Code that has derived something from the pattern of W, such as a symbolic factorization or the positions of its entries in nonzeros(W), is then silently out of date.

A fixed sparse array rules that out. It is a destination whose sparsity pattern never changes: the stored values can be overwritten, and no entry can be added or removed. SparseArrays.fixed makes one, with the arguments of sparse or from a sparse array, which it copies. Three rules describe everything a fixed array does; the SparseArrays.FixedSparseCSC docstring lists the functions each one covers.

A write lands inside the pattern or throws. A write, such as W .= ..., copyto!, mul! or W[i, j] = v, stores a value at each stored entry, a zero included, and leaves the pattern alone. What is written need not fill the pattern: the stored entries it leaves out become zero. A write that needs an entry where the pattern has none throws an ArgumentError, and the kernels of this package check for that before they change any value. Writing through nonzeros(W) is always allowed.

julia> J = sparse([1.0 2 0; 0 3 0; 4 0 5]); M = sparse(1.0I, 3, 3);

julia> nnz(M .- J)   # the entry at (1, 1) cancels and is not stored
4

julia> W = SparseArrays.fixed(M + J);

julia> W .= M .- J
3×3 SparseArrays.FixedSparseCSC{Float64, Int64} with 5 stored entries:
  0.0  -2.0    ⋅
   ⋅   -2.0    ⋅
 -4.0    ⋅   -4.0

julia> W[1, 3] = 1.0
ERROR: ArgumentError: cannot store a new entry at (1, 3) in a FixedSparseCSC, its sparsity pattern is read-only
[...]

A function that exists to change the pattern throws. dropzeros!, droptol!, fkeep!, tril!, sort!, permute! and the like refuse a fixed array as the argument they change. Their out-of-place forms work, because of the next rule.

julia> dropzeros!(W)
ERROR: ArgumentError: cannot `dropzeros!` a FixedSparseCSC: it would change the sparsity pattern, which is read-only; apply it to a writable copy, `SparseMatrixCSC(A)`
[...]

Reading a fixed array gives an ordinary result. As an operand, a fixed array behaves as the SparseMatrixCSC or SparseVector with the same entries, and what comes back is what that array would give. Being fixed is a property of one array, not of its values, so it does not carry over to indexing, arithmetic, broadcasting, concatenation or similar. Only copy(W) is fixed, and shares the pattern of W; SparseArrays.fixed(A) fixes any other result, and SparseMatrixCSC(W) gives a writable copy.

julia> typeof(2W), typeof(similar(W))
(SparseMatrixCSC{Float64, Int64}, SparseMatrixCSC{Float64, Int64})

julia> V = copy(W); rowvals(V) === rowvals(W)
true

The factorizations accept a fixed matrix, which is what makes reusing a symbolic factorization safe: see "Reusing a factorization" on the Sparse Linear Solvers page.

Supertype for matrices stored in compressed sparse column (CSC) format with element type Tv and index type Ti. SparseMatrixCSC is the concrete type; packages define their own subtypes to reuse the CSC kernels on other storage.

A subtype must define size and the three storage accessors getcolptr, getrowval and getnzval, which are the only accessors the methods of this package call on it. They return vectors that alias the matrix and satisfy the invariants documented for the SparseMatrixCSC constructor: getcolptr(S) has length size(S, 2) + 1, starts at 1 and is nondecreasing; getrowval(S) and getnzval(S) have length getcolptr(S)[end] - 1; and within each column the row indices are sorted, unique and in 1:size(S, 1). Everything else, such as nnz, nzrange, indexing, copy, similar and the sparse linear algebra, is derived from these. rowvals and nonzeros are not defined for such a subtype.

Subtypes written while rowvals and nonzeros were the only exported accessors implement those in place of getrowval and getnzval, which fall back to them. This remains supported, but is planned to stop being supported in SparseArrays 2.0.

SparseVector{Tv,Ti<:Integer} <: AbstractSparseVector{Tv,Ti}

A sparse vector, with stored values of type Tv at indices of type Ti. SparseVector(n, nzind, nzval) wraps, without copying, a vector nzind of indices, which must be sorted and unique, and the vector nzval of the values at those indices, as a vector of length n. sparsevec builds one from unsorted indices, and sparse from a dense vector.

SparseArrays.SparseMatrixCSC — Type
SparseMatrixCSC{Tv,Ti<:Integer} <: AbstractSparseMatrixCSC{Tv,Ti}

Matrix type for storing sparse matrices in the Compressed Sparse Column format. The standard way of constructing SparseMatrixCSC is through the sparse function. See also spzeros, spdiagm and sprand.

SparseMatrixCSC(m::Integer, n::Integer, colptr::Vector, rowval::Vector, nzval::Vector)

Wrap existing CSC arrays as an m × n matrix without copying them. Column j holds the entries nzval[k] in rows rowval[k] for k in colptr[j]:(colptr[j+1] - 1).

Only colptr and the lengths of rowval and nzval are checked. The row indices are not inspected, and must be strictly increasing within each column and lie in 1:m. The kernels in this package rely on that. A matrix with unsorted, repeated or out-of-range row indices is constructed silently and then gives inconsistent results. To construct a matrix from repeated indices, use sparse, which adds up their values. See the manual for how to repair such arrays.

sparse(I, J, V,[ m, n, combine])
sparse(IJ, V,[ m, n, combine])

Create a sparse matrix S of dimensions m x n such that S[I[k], J[k]] = V[k]. The combine function is used to combine duplicates. If m and n are not specified, they are set to maximum(I) and maximum(J) respectively. If the combine function is not supplied, combine defaults to + unless the elements of V are Booleans in which case combine defaults to |. All elements of I must satisfy 1 <= I[k] <= m, and all elements of J must satisfy 1 <= J[k] <= n. Numerical zeros in (I, J, V) are retained as structural nonzeros; to drop numerical zeros, use dropzeros!.

The positions may also be given as one vector IJ of two-dimensional CartesianIndexes, such that S[IJ[k]] = V[k].

SparseArrays.sparse! — Function
sparse!(I::AbstractVector{Ti}, J::AbstractVector{Ti}, V::AbstractVector{Tv},
        m::Integer, n::Integer, combine, klasttouch::Vector{Ti},
        csrrowptr::Vector{Ti}, csrcolval::Vector{Ti}, csrnzval::Vector{Tv},
        [csccolptr::Vector{Ti}], [cscrowval::Vector{Ti}, cscnzval::Vector{Tv}] ) where {Tv,Ti<:Integer}

Parent of and expert driver for sparse; see sparse for basic usage. This method allows the user to provide preallocated storage for sparse's intermediate objects and result as described below. This capability enables more efficient successive construction of SparseMatrixCSCs from coordinate representations, and also enables extraction of an unsorted-column representation of the result's transpose at no additional cost.

This method consists of three major steps: (1) Counting-sort the provided coordinate representation into an unsorted-row CSR form including repeated entries. (2) Sweep through the CSR form, simultaneously calculating the desired CSC form's column-pointer array, detecting repeated entries, and repacking the CSR form with repeated entries combined; this stage yields an unsorted-row CSR form with no repeated entries. (3) Counting-sort the preceding CSR form into a fully-sorted CSC form with no repeated entries.

Input arrays csrrowptr, csrcolval, and csrnzval constitute storage for the intermediate CSR forms and require length(csrrowptr) >= m + 1, length(csrcolval) >= length(I), and length(csrnzval >= length(I)). Input array klasttouch, workspace for the second stage, requires length(klasttouch) >= n. Optional input arrays csccolptr, cscrowval, and cscnzval constitute storage for the returned CSC form S. If necessary, these are resized automatically to satisfy length(csccolptr) = n + 1, length(cscrowval) = nnz(S) and length(cscnzval) = nnz(S); hence, if nnz(S) is unknown at the outset, passing in empty vectors of the appropriate type (Vector{Ti}() and Vector{Tv}() respectively) suffices, or calling the sparse! method neglecting cscrowval and cscnzval.

On return, csrrowptr, csrcolval, and csrnzval contain an unsorted-column representation of the result's transpose.

You may reuse the input arrays' storage (I, J, V) for the output arrays (csccolptr, cscrowval, cscnzval). For example, you may call sparse!(I, J, V, csrrowptr, csrcolval, csrnzval, I, J, V). Note that they will be resized to satisfy the conditions above.

For the sake of efficiency, this method performs no argument checking beyond 1 <= I[k] <= m and 1 <= J[k] <= n. Use with care. Testing with --check-bounds=yes is wise.

This method runs in O(m, n, length(I)) time. The HALFPERM algorithm described in F. Gustavson, "Two fast algorithms for sparse matrices: multiplication and permuted transposition," ACM TOMS 4(3), 250-269 (1978) inspired this method's use of a pair of counting sorts.

SparseArrays.sparse!(I, J, V, [m, n, combine]) -> SparseMatrixCSC

Variant of sparse! that re-uses the input vectors (I, J, V) for the final matrix storage. After construction the input vectors will alias the matrix buffers; S.colptr === I, S.rowval === J, and S.nzval === V holds, and they will be resize!d as necessary.

Note that some work buffers will still be allocated. Specifically, this method is a convenience wrapper around sparse!(I, J, V, m, n, combine, klasttouch, csrrowptr, csrcolval, csrnzval, csccolptr, cscrowval, cscnzval) where this method allocates klasttouch, csrrowptr, csrcolval, and csrnzval of appropriate size, but reuses I, J, and V for csccolptr, cscrowval, and cscnzval.

Arguments m, n, and combine defaults to maximum(I), maximum(J), and +, respectively.

Julia 1.10

This method requires Julia version 1.10 or later.

SparseArrays.nonzeros — Function
nonzeros(A)

Return a vector of the structural nonzero values in sparse array A. This includes zeros that are explicitly stored in the sparse array. The returned vector points directly to the internal nonzero storage of A, and any modifications to the returned vector will mutate A as well. See rowvals and nzrange.

For a view of all rows and some columns of a sparse matrix, nonzeros returns a view of the parent's storage holding the entries of A only, so length(nonzeros(A)) is nnz(A) and writes to it mutate the parent. SparseArrays.nzrange — Function
nzrange(A, col::Integer)

Return the range of positions of the stored entries of column col of the sparse matrix A in rowvals(A) and nonzeros(A). Looping over the columns and over this range visits every stored entry once, in storage order.

Examples

julia> A = sparse([1, 3, 2], [1, 1, 3], [10, 30, 20]);

julia> rows, vals = rowvals(A), nonzeros(A);

julia> [(rows[k], j, vals[k]) for j in axes(A, 2) for k in nzrange(A, j)]
3-element Vector{Tuple{Int64, Int64, Int64}}:
 (1, 1, 10)
 (3, 1, 30)
 (2, 3, 20)

The same loop works on a view of all rows and some columns of A, whose nzrange indexes the rowvals and nonzeros of the view. For a view of a range of columns each call is O(1); for another column subset nzrange(A, col) sums the lengths of the preceding columns, so it is O(col).

Warning

Adding or removing a stored entry invalidates the range, so do not change the pattern of the matrix while iterating.

Fixed pattern (experimental)

SparseArrays.fixed — Function
fixed(x...)

Experimental. Like sparse but returns a sparse array whose sparsity pattern is read-only: stored entries can change value, but none can be added or removed.

fixed(A) of a writable sparse array A copies it, so the result shares no memory with A. Use SparseArrays.move_fixed to reuse the buffers of A instead. fixed(F) of a fixed array is copy(F): it copies the values and shares the pattern.

A write into the result keeps every stored entry and throws an ArgumentError, before changing anything, when it needs an entry outside the pattern. A function whose purpose is to change the pattern, such as dropzeros! or tril!, throws. Operations that read the result return ordinary arrays: of the out-of-place functions only copy returns a fixed array, sharing the pattern. See Sparse arrays with a fixed pattern.

  ⋅   0.0

julia> W[2, 1] = 1.0

[...]

julia> typeof(W + W)

SparseArrays.FixedSparseCSC — Type
FixedSparseCSC{Tv,Ti<:Integer} <: AbstractSparseMatrixCSC{Tv,Ti}

Experimental. A sparse matrix in CSC format whose sparsity pattern is read-only: stored values can be overwritten, but no entry can be added or removed.

A FixedSparseCSC is a destination for in-place writes. As an operand it behaves as the SparseMatrixCSC with the same entries, and results are not fixed; only copy returns a FixedSparseCSC, which shares the pattern. See Sparse arrays with a fixed pattern.

A write stores a value at each stored entry, a zero included, and throws an ArgumentError when it needs an entry that the pattern does not have. That holds for W .= ..., map!, copyto!, mul!, fill!, rmul!, lmul!, rdiv!, scalar and block setindex!, assignment through a column view, and for a result written into a fixed destination by transpose!, permute! or circshift!. The kernels of this package check before they change any value. Where the package has no method for a sparse destination, Julia's generic one writes one entry at a time: a broadcast into a view, a dense source as in W .= D or copyto!(W, D), axpy!(a, A, W), or mul! with a dense factor. Such a write stops at the first entry outside the pattern, with the entries before it already written. Writing through nonzeros(W) is always allowed.

A function whose purpose is to change the pattern throws for a fixed argument: dropzeros!, droptol!, fkeep!, tril!, triu!, dropstored!, sort!, permute!, invpermute!, reverse!, circshift!, swaprows! and swapcols!. Their out-of-place forms work, and return an ordinary array.

Base.:* — Method
*(A::AbstractSparseMatrixCSC, B::AbstractSparseMatrixCSC)

Product of two sparse matrices, a SparseMatrixCSC whose index type is the promotion of those of A and B.

The cost is proportional to the number of products of stored entries, not to the size of the result. An entry is stored wherever such a product contributes, even when the contributions cancel or a factor holds a stored zero; dropzeros! removes them.

Operator p-norm of the sparse matrix A, for p equal to 1, 2 or Inf.
