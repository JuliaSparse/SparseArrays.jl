# SuiteSparse wrappers

`src/solvers/wrappers.jl` is generated by `gen/`. Never edit it by hand: change
`gen/prologue.jl`, `gen/generator.toml` or `gen/generator.jl` and regenerate.

## Regenerating the wrappers

1. `cd gen`.
2. In `Makefile`, set the SuiteSparse version (`VER`), the `SuiteSparse_jll` build number
   (`JLL_BUILD`), and `SHA256` to the `x86_64-linux-gnu` archive's checksum from that
   release's `SuiteSparse_jll` `Artifacts.toml`.
3. Run `make` (`make JULIA='julia +nightly'` to select Julia). The wrappers are written to
   `src/solvers/wrappers.jl`; the banner at its top comes from `prologue.jl`.

Downloads and extracted headers are cached by version and build number; `make clean`
removes the current release's cache.

- `Makefile` downloads the `x86_64-linux-gnu` build of `SuiteSparse_jll` for the headers,
  which are platform independent. `generator.jl` takes that unpacked directory as its only
  argument and never reads the running Julia's `SuiteSparse_jll`, a fixed stdlib.
- Keep the version in `Makefile` in sync with the `SuiteSparse_jll` compat entry in
  `Project.toml`.
- `generator.jl` lists the headers to wrap, in an order where a header comes before any
  header that includes it; otherwise its wrappers move in the output. `library_names` in
  `generator.toml` maps each header to its library by pattern against the path, so `/amd.h`
  and `/colamd.h` carry the separator that keeps the first from matching the second. AMD
  and COLAMD are BSD-licensed, so their wrappers may be called from outside `src/solvers/`.
- Run `make` before changing the generator. It must reproduce the committed
  `wrappers.jl` byte for byte, so that the diff afterwards is only what your change causes.
- To drop a macro Clang.jl cannot handle, add it to `output_ignorelist` in `generator.toml`.

## Upgrading SuiteSparse

1. Update SuiteSparse in Yggdrasil.
2. Update the version here and regenerate the wrappers.
3. Run BumpStdlibs to update the SparseArrays.jl version in Julia master.
4. Update the relevant stdlibs in Julia to pull in the new releases.

The bump cannot be tested here until nightly bundles the new jll, so its CI is expected to
be red. Do not delete the merged bump PR's branch.

## Upgrading Clang.jl or JuliaFormatter

Change the compat bound in `gen/Project.toml` (a breaking Clang.jl release may need
`generator.jl` adapted), run `make`, and commit the regenerated `wrappers.jl` with the
compat change. A diff in the wrappers is the new release's output change; say so in the PR.
